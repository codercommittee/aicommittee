# Changelog

## 0.2.4 (1 November 2026)

What an end-to-end run with local Ollama models (qwen3, llama3.2, gemma3 as the three coders, nomic-embed-text as the embedder) showed. Every adapter takes `temperature` and `timeout` besides `max_output_tokens`, sends the temperature only when one is given, and records all three in its `describe()` record, so a resume under other settings is refused. The command line's `code` and `score` take `--max-output-tokens`, `--temperature` and `--timeout`, applied to every model built from a spec, coders and the LLM referee alike; a referee that runs out of output tokens (a model that thinks before it answers) now says so and names the option. The documented commands ran on real study items of every dataset with those models, with resumes, retries and the interrupted-run recovery exercised on the way.

## 0.2.3 (1 November 2026)

The points of a second audit of 0.2.2. A transport error whose text carries the configured URL no longer leaves its password in an answer's reason: every error text an answer records is scrubbed of URL credentials. An interrupted `Run.save` leaves the manifest with the seats' identities before any answer is written, and a manifest from before the record existed adopts a seat only when the stored answers' own model agrees. The LLM referee's record binds the endpoint and the adapter's settings, the template, the system prompt and the fields, so decisions made under one configuration are never served to another; a record written by 0.2.2 is upgraded, not refused. An append-only file's tail is repaired before every append, and a failed append drops the store's cache, so a retry after a failed write leaves a store that loads and asks nothing twice. A run built by hand records the referee it scores with when saved (the referee object, not a stale record); a referee kind the package cannot rebuild is served from its recorded decisions, and a realization it never decided is named at scoring time. Secrets echoed by an error in any other form (an API key from the environment or the adapter, a bare password, a URL with a raw `@` in its password or JSON-escaped slashes) are redacted too; a seat adopted by a manifest without records is also checked against the endpoint its stored answers name. Left as it is: saving a run whose answers are identical to the stored ones does not rewrite them, so the first record's evidence (attempt counts, response ids) stands.

## 0.2.2 (1 November 2026)

The fixes after an external adversarial audit of 0.2.1, verified case by case against its reproductions and against the study's stored runs (parity unchanged).

Files and the store. JSON Lines files split on the newline alone, so U+0085, U+2028, U+2029 and the other separators a JSON string may hold raw round-trip (they broke item files and every store holding such text). A crash inside the final append leaves a line without its newline: the next load drops and repairs it and the slot is asked again; `run.json` and the spaces are written atomically. Saving a run into a directory that holds different answers, vectors or decisions for the same slots is refused, never merged. A task record's explicit empty `aux`, `fields`, `codebook` or `per_answer` survives the manifest; stored decisions must be booleans; an ok answer without a raw reply is stored re-validatable; a loaded answer keeps its attempt count; a manifest or an answer line of the wrong shape is a `StoreError`, never a traceback. Item files may start with a BOM.

The referee. `LoggedReferee` serves a recorded decision bound to the same pre-match before asking its referee, so a resumed or repeated run never pays twice for the same question and never replaces its decisions. A run carries `provenance`: the referee's configuration and each seat's identity (`describe()` on coders, models and referees), written into `run.json`; a resume with another referee, or another model under a seat, is refused by name, and a manifest from before the record gains it. `Run.load` scores with the recorded referee (the band rule at its threshold, or the recorded decisions), so the command line's `levels.json` and a later load agree; `Run.save` copies the recorded decisions of a loaded or replayed run; a `tuples` run whose LLM referee was never logged is refused. The study replay defaults to the stored referee decisions for the `tuples` kind.

Coders. An invalid or refused answer is asked again inside one budget of attempts, the adapter's transport attempts counting toward it, as the study's runner did; a refusal that survives the budget is final, and a stored refusal is reused only when it spent the budget it is asked under (a refusal stored by 0.2.1, which gave up at the first one, is asked again once). The Anthropic, OpenAI and OpenAI-compatible adapters classify the policy finishes (`refusal`, `content_filter`) as refusals. The paid replies a budget threw away are recorded in the answer's audit. A garbage reply (a 4,301-digit integer, nesting beyond the recursion limit) is an invalid answer, not an exception. The OpenAI-compatible adapter strips URL credentials before they reach an identity. Embedding requests above 2,048 spans are batched.

Inputs and numerics. The comparison pairs items by typed id (`7` and `"7"` are two items). Coder names cannot hold `:` or `|` or surrounding whitespace; codebook names cannot carry surrounding whitespace. The mock embedder never collapses to the zero vector. The cosine survives vectors of extreme magnitude by an exact power-of-two scaling and raises on a non-finite result; ordinary vectors are summed as before, bit for bit.

Left as is: the mock embedder lowercases with the interpreter's Unicode tables, as the study's mock does, so two characters added in Unicode 16 embed differently on Python 3.14 than on 3.11; it is a stand-in, not a measurement.

## 0.2.1 (31 October 2026)

The test campaign before the first PyPI release. Every code block of the README and of `docs/study.md` runs as a test; property-based tests over validation, similarity, assignment, alignment, combination, the comparison table and the file formats; integration tests under failure (a coder that crashes and the resumed run, mixed statuses, every answer kind through the command line, logged and replayed referee decisions); a packaging test that builds the sdist and wheel, checks them with twine and installs the wheel into a fresh environment; mypy strict over the tests and the parity harness too; a docstring on every public name; a coverage floor; CI on Python 3.11 to 3.14 and a release workflow with PyPI trusted publishing. Code changes: `Item` is typed to accept any set of label names or any sequence of relations and stores the normalized reference (`ReferenceInput`); `MissingVector` is renamed `MissingVectorError`; the README's sentence-transformers example imports `FunctionEmbedder`.

## 0.2.0 (31 October 2026)

Files in and out (`read_items`, `write_items`, writers for predictions, scores, the comparison table, agreement and the pick); saved, resumable and replayable runs (`RunStore`, `collect(store=...)`, `Run.save`, `Run.load`, `LoggedReferee`, `StoreReferee`); `OpenAICompatibleEmbedder` and `FunctionEmbedder`; the study's five tasks with their prompts as package data (`codercommittee.study`); the `codercommittee` command line (`code`, `score`, `compare`, `agreement`, `pick`, `tasks`); `parity/export_items.py` and the study recipe in `docs/study.md`; the parity command checks the packaged prompts against every stored request. A relation that omits a span field equals one giving it as empty.

## 0.1.0 (31 October 2026)

First version: the four aggregation structures as one combine operator (one answer; one coder asked three times; the majority vote with alignment; the pool at k of nine), deduplication, alignment with the band rule or an LLM referee, scoring for the four answer kinds, levels, the comparison table (gap, interval, blind pick, spread, premium), agreement rates, the labelled-sample pick, mock and replay coders, thin adapters for Anthropic, OpenAI, Google and OpenAI-compatible endpoints, mock and OpenAI embedders, and the parity harness against the study's stored runs.
